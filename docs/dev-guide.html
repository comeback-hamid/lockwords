03

Agent rules

Short, always on. AGENTS.md for everything; each app's CLAUDE.md for its commands and layers. Add a line only when an agent makes the same mistake twice.

✓

Always

  • Tests first: write the test, run it, see it fail for the expected reason, then build.
  • Agents run the checks themselves and report. Never ask a human to run them.
  • Planning is not permission to build. Stop after the proposal.
  • "(open)" means not decided. Ask, never invent.
  • Check the docs for our Expo SDK version (and docs.expo.dev/llms.txt), not memory.
  • npx expo install, never npm install.
  • Colors and sizes come from theme.ts. No raw values.
  • Plain English in docs and specs. Short sentences.
  • Better idea? Suggest it, don't just do it. If the agent thinks there is a better way than this guide, it tells Hamid what and why, then waits for his OK. Never change the plan quietly.
✕

Never

  • Edit or delete a test to make it pass. If it looks wrong, stop and ask.
  • Commit secrets, .env files or *.p8 keys.
  • Log tokens, emails or secrets. Store tokens only in secure storage.
  • Push to main or force-push.
  • Edit ios/, android/ (generated) or openspec/changes/archive/.
  • Add a package without saying why. A native one needs a new dev build.
  • Invent API shapes. They follow the server's OpenAPI document.
  • Re-build SRS rules in the app. The server decides.
⚡

Claude hooks

Stop: run the app's tests, typecheck, lint; fail = keep working. PreToolUse: block test edits during apply, and edits to .env and the archive. SessionStart: print active changes.

🔑

iOS Keychain

It survives deleting the app. List every secure key in one SECURE_KEYS list and clear them on a fresh install.

Three databases

Production · lockwords_dev (local, for the app) · lockwords_test (name must contain "test"). Dev servers never use production settings.

AI is always faked

One fixture replaces Langfuse and the model. Real model calls are switched off for the whole suite. Flows get seeded answers.

Flow areas

Each flow has exactly one tag: onboarding, new-words, review, my-words, speak, widget. Shared code changed → run all.

Every bug a person or the verifier finds becomes a new test first, then the fix. Later, not now: mutation testing, contract fuzzing, coverage targets, nightly performance runs (do one performance check before launch).

Many agents at once: stay fast

On one Mac the slow part is not the code. It is the Maestro pass before every push: all flows take about an hour, and every merge makes the other sessions test again. When several sessions work on one batch, these two rules apply (Hamid, 2026-11-23). Hamid says at the start of a batch that it runs this way.

1 · Area-only tests after a merge

After a session merges origin/main, it runs only the flows of the areas its change touches: LOCKWORDS_E2E_AREAS=review,onboarding (its own new flow is among them). Never the full pass again. The PR names the areas it ran.

2 · No local simulator run before a push

Unit tests, typecheck and lint pass → git push --no-verify. GitHub CI must be green before a merge. The PR says: "Pushed without the local Maestro pass". A feature still records its own flow once, for the video.

What keeps this safe. When the whole batch is merged, one full pass of all flows runs on main, on one simulator with nothing else running, and it records the video for Hamid. What it finds is fixed before any build goes to a phone or to TestFlight. No full pass, no build. A single session working alone keeps the normal pre-push pass.
More in docs/parallel-work.md ("Faster with many sessions"): how many simulators this Mac can run, and how to tell a real failure from a busy machine.
08

Building AI features

Decks, Use it feedback, Kai's replies, deck pictures, the Speak judge. One pattern for every AI task.

⌁

Code

  • One client (server/src/llm/client.ts) for every model call: fetch prompt, run it, force JSON, validate, send back once if invalid, trace.
  • One module per task: make_deck, use_it_feedback, kai_reply, speak_judge, deck_picture. Returns nothing on a bad answer; the service decides the fallback.
  • Every call has a timeout and a message for the user. Failed = nothing saved. Good answers are saved, so the same request never pays twice.
  • AI keys only on the server. The app never holds one.
✎

Prompts

  • Live in Langfuse, versioned, label production.
  • A draft file per prompt in the repo: text, model + settings, and the test results that chose the model (pass rate, median time, slow cases, cost per call).
  • A small eval set per prompt (10–20 cases): deck fits the level, corrections are right and kind. Rerun before promoting a new version.
  • Batch jobs (ready-made decks, picture sheets) have --dry-run and --limit: 20 → read → 1,000 → check → all. Print the cost.
09

Testing Speak

A 3-minute voice talk with Kai. Answers are never the same twice, so test in layers.

1Logic + screens

Unit tests: 3:00 timer, word ticks (also "ordered" for "order"), mute sends nothing. Maestro with a fake Kai: every state, mic denied, internet drops.

2Student bot + judge

An LLM plays a learner (mistakes, own-language words, short answers), a voice in its own language gives the accent, ffmpeg adds noise. It talks to the real Kai. A judge AI scores level fit, target words, kind corrections, understood the accent, student talks more.

3Numbers + you

Reply under ~1 s, Kai stops when interrupted, transcript accuracy per language, cost per talk. Plus 10–20 real recordings, and you talking to Kai weekly.

Ship rule: 20–30 bot talks after every Kai prompt change. If the average or any language drops, don't ship. Start with layer 1; add the bot + judge before launch.
10

Ship safely, often

↻

Updates

Expo EAS Update sends JS fixes the same day. Store releases only for native changes (widget, new native package).

⚑

Feature flags

PostHog. Unfinished work hidden. Safe default = off. Delete a flag at 100%.

✈

TestFlight per feature

Built on GitHub Actions from the branch, so checkpoint 2 happens before merge.

⬆

Add-only migrations

Only add tables and columns. Drop or rename in a later deploy, so a rollback always works.

♥

Health check + rollback

Deploy → migrate → GET /health for 60 s → back to the old version if it fails.

✓

Builds check themselves

Release build fails if the API address or the RevenueCat key is missing or wrong, and checks the final app contains them.

Two agents at once only with worktrees (one folder per branch) and only when they touch different files. Your review time is the real limit. The full rules are in docs/parallel-work.md.

Learn from users

◔

Events

object_action, lowercase, past tense: deck_created, card_swiped, widget_added, talk_finished. Context in properties. Listed in events.md.

☺

Speak score

Per language: one-tap rating + finished 3:00 + came back in 7 days + judge score on a consented sample. Alert when it drops.

⚙

Privacy

Store little: login, name, languages, level, goals. Keep Speak text only, never audio. Delete account in the app removes everything. Each user reads only their own rows.
