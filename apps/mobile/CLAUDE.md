# apps/mobile

Expo SDK 58, React Native 0.88, TypeScript strict, Expo Router (routes in `src/app/`). iOS first, then Android and web.

## Commands (run from this folder)
```bash
npx expo install <package>   # ALWAYS, never npm install here
npm run ios                  # dev build on the iOS simulator (npx expo run:ios)
npm run android              # optimized dev build on the Android emulator (see "Android" below)
npm start                    # dev server for an existing dev build
npm test                     # Jest + React Native Testing Library
npm run typecheck            # tsc --noEmit
npm run lint                 # expo lint
npm run web                  # the app in a browser (see "Web" below)
npx expo-doctor              # dependency and config check
```
Maestro flows run from the repo root: `npm run e2e -- --areas review`.

## Web
The same app runs in a browser (`web-build`). Rules for code that must work there:
- Storage: import `@/platform/key-store`, never `expo-secure-store` (it has no browser version).
- Pop-ups: `confirmAction` / `tell` from `@/platform/dialog`, never `Alert.alert` (it does nothing on the web).
- A file `name.web.tsx` replaces `name.tsx` in the browser: `(tabs)/_layout.web.tsx` (our own bottom tab bar), `kai/kai-canvas.web.tsx` (live Kai on the browser's 2D canvas, no Skia), `components/meadow-canvas.web.tsx` (the moving meadow, same way).
- CI builds the web app (`npx expo export -p web`), so a phone-only import fails the pull request.
- Browser tests: `npm run e2e:web` from the repo root (Playwright: Chromium, Firefox, WebKit; see `e2e/README.md`, "Web"). Four flows: `first-run` (phone-size, three engines), `wide` (1440 px, three engines), `touch` (a phone's browser with a touch screen), `edges` (reloads, odd addresses, no connection, keys behind another tab; two engines). Run it when you change a shared screen or anything in `src/platform/`. It is not in CI.
- Live Kai and the meadow in a browser: the frame still comes from `kai/step.ts` (Kai) and `progress/meadow-motion.ts` (the meadow, a port of the phone's motion: change both); `kai/draw-2d.ts` and the meadow's painter put it on a `<canvas>`; `platform/frame-loop.ts` runs the loop and draws nothing while the canvas is hidden. Reduce Motion = the still pictures. `KaiCanvas` and `MeadowCanvas` in the `.web` files must stay free of hooks at the top (tests call them as plain functions): hooks live in `LiveKai` / `LiveMeadow`.
- The window decides the layout (`@/platform/web-layout`: `webMode(width)` is `phone` under 600, `tablet` to 1023, `desktop` from 1024; always `phone` on the phone app). `WebFrame` (`@/platform/web-frame`) centers every screen outside the tabs in a 480 column; `(tabs)/_layout.web.tsx` puts the tabs in a side bar on desktop and pads each tab screen to its column (600; Review 480). Never read the window's width to size a part of a screen: use `useContentWidth()`. Never put a max width inside a shared screen for the web: the padding comes from the layout.
- `KeyHints` (`@/platform/key-hints`) names the card's keys under the round on desktop only. `public/` holds the page (`index.html`, a copy of Expo's template plus our lines), `manifest.json` and the home screen icons; `scripts/web-page.test.mjs` checks them.
- A browser can reload any address. Screens that live on memory must cope: onboarding (`app/onboarding/_layout.web.tsx` + `@/platform/onboarding-reload`: lost answers start over), Use it (`@/platform/no-round`: no round opens Review), an unknown address (`app/+not-found.tsx`) and the router's `/_sitemap` (`app/_sitemap.tsx`) open the start. A new screen that reads a store kept in memory needs the same care.
- **Screens of the other tabs stay in the page, drawn, under the open tab** (not `display: none`). "Is my screen showing?" is therefore `roundOnTop()` in `@/platform/round-keys` (what the page shows at the screen's middle), never `offsetParent` alone. A window key listener must use it.
- A multi-line text box does not grow in a browser by itself: `useGrowingTextBox` (`@/platform/grow-text-box`), used by `Composer`.
- In a browser `accessibilityState` is not enough for "selected": also pass `aria-selected` (found by the wide test).
- A real keyboard: `sendOnEnter` (`@/platform/enter-key`) on a multi-line text box makes Enter send and Shift+Enter a new line; `useRoundKeys` (`@/platform/round-keys`) gives the review card its keys (Space flips, arrows answer, Backspace undoes; it listens only while the round's card is on screen). Both do nothing on the phone.
- The web tab bar is our own (`@/platform/web-tab-bar`), passed to `Tabs` as `tabBar`. `installPageStyle` (`@/platform/page-style`) adds the few page-wide CSS rules a browser needs.
- Browsers differ: Firefox drags a picture by itself (off, `installPageStyle`); Safari records mp4 and the others webm or ogg (`audioFormat(uri, blob.type)`); the mic note for a browser is `micRefused()` (`@/platform/dialog`).
- The dev server for a browser check: `npm run web`. Do not start it with `CI=1`: Metro then stops watching files and serves old code.

## Android
The same app runs on Android (since 2026-11-25). Package `com.comebackhamid.lockwords`. Rules for code that must work there:
- **Build:** `npx expo run:android --variant debugOptimized --port <your Metro port>` (the port becomes part of the build). Use `debugOptimized`, not plain `debug`: the app draws Kai and the meadow on the UI thread, and with unoptimized native code the Progress meadow runs at 8 frames a second. `android/` is generated: Android setup goes in `app.json` and in the config plugins in `plugins/`.
- **This Mac's network gets 404 from `dl.google.com`** (Google's package and SDK server; found 2026-11-25). Builds here use Google's other address through a local Gradle folder that is not in git: start every Gradle or Expo Android command with `GRADLE_USER_HOME=~/.config/lockwords/gradle-home` (its `init.d/google-mirror.init.gradle` adds `https://edgedl.me.gvt1.com/edgedl/android/maven2`). New SDK parts (a platform, build tools, an NDK) are downloaded by hand from `https://edgedl.me.gvt1.com/edgedl/android/repository/` and checked against the SHA-1 in `repository2-3.xml` there. CI (GitHub) uses Google directly.
- **The emulator:** `emulator -avd Pixel_9_Pro -gpu host -feature -Vulkan` (with Vulkan every screenshot is white), then `adb reverse tcp:<port> tcp:<port>` for the server, Supabase (54321) and Metro, so `.env.local` keeps its `localhost` addresses.
- **The icon** is the app icon's two word cards on white (Hamid's sketch, 2026-11-25), as an Android adaptive icon: `npm run android-icon:gen` draws `assets/images/android-icon-foreground.png` and `-monochrome.png` with the measures of `scripts/gen-app-icon.mjs`, made smaller so every launcher shape keeps the whole picture. The same script draws **the Android splash**, `assets/images/splash-android.png`: Kai alone (`app.json`, `expo-splash-screen` → `android`). Android cuts the splash to a circle, so the iOS picture with the name under Kai does not fit.
- **Edge to edge:** Android draws the app under the status bar and the keyboard. So: every screen with a text box passes `behavior={avoidKeyboard()}` (`components/chat/keyboard.ts`) to its `KeyboardAvoidingView`; the root layout asks for dark status bar icons (`<StatusBar style="dark" />`).
- **A chat scrolls to its end with `scrollChatToEnd` only.** On Android it scrolls again on the next frame, because the list does not know its new height yet in the same frame (the reply options stayed under the text box).
- **`plugins/with-android-debug-splash.js`:** debug builds only. It lets Android remove the splash by itself. Without it a debug build left a start animation hanging on the window, and every tap from a test tool took 12 seconds. Release builds keep Expo's fade.
- **A control that is hidden from screen readers but still on the screen** (a button under a row, a card under a card) keeps its name for test tools on Android. Give it `accessibilityLabel={nameWhenShown(name, shown)}` (`src/platform/hidden-name.ts`).
- **The tab bar** is Material's on Android: `indicatorColor` and `rippleColor` on `NativeTabs` are our light green. It is a normal bar under the screen, so `layout.tabBarClearance` is 0 there (92 on iOS, where the bar floats).
- **Back** is the system's: it closes the keyboard, goes back one screen, opens the first tab from another tab, and leaves the app from the first tab. No screen changes that.
- **Secure storage** is deleted with the app's data on Android (on iOS the Keychain stays), so `clearOnFreshInstall` finds nothing to clear there. It still runs: it costs nothing.
- **The Android home screen widget** is native code in `modules/lockwords-widget` (Kotlin, its own layouts; see its README and `docs/architecture.md`). The app's side: `src/widgets/sync.android.ts` (Android's copy of `sync.ts`) and `android-widget.ts`. `src/widgets/sync.ts` stays iOS only. A change in `modules/` needs a new Android build. Kai's pictures there are written by `npm run widget:kai`.
- **A release build:** `npm run android:release` from the repo root (`docs/android-release.md`). `plugins/with-android-release-signing.js` signs it with the upload key when the key's Gradle properties are set; the key is never in git.
- **Maestro on Android:** `npm run e2e -- --platform android` (see `e2e/README.md`, "Android").

## Layers
- `src/app/`: screens only (Expo Router). `(tabs)/`: New words · Review · Progress (v1, decided 2026-11-16). Progress = the My words page as a tab. Speak comes after v1.
- `src/components/`: shared UI. Copy Figma component names (Chat bubble, Reply option, Composer, Kai header, Level square…).
- `src/theme/theme.ts`: all tokens from Figma. No raw colors or sizes anywhere else.
- Fonts by script: a text that can be in any language (a word, a meaning, a title, a name, Kai's lines) uses `LangText` (`src/components/lang-text.tsx`) or adds `fontFor(text, style)` (`src/theme/script-font.ts`): Mona Sans for Latin, Vazirmatn for the Arabic script, the phone's font for every other script. `KaiText` does it by itself.
- `src/theme/fonts.ts`: the fonts loaded at start (Mona Sans 400/500/600, JetBrains Mono 500/700). Use `type.*` styles; never set `fontWeight` (the weight is in the font name).
- `src/kai/`: live Kai. `character-spec.json` is Kai's data (never type Kai numbers into code). `step.ts` is the port of `step()` from `docs/design/CHARACTER.html` (a worklet, tested in Jest); `kai-canvas.tsx` draws it with Skia on the UI thread; `kai.tsx` is the one component screens use: `<Kai state? talking? listening? playKey? progress? size? onPress? />`. `talking` (Kai's line is being typed or played) and `listening` (the learner types or speaks) show over a resting state only (idle, waiting, sleeping); `KaiHeader` passes both on. `useWaves()` (`use-waves.ts`) replays the hello every few seconds (O0, O2). One-shot states (greeting, celebrate, oops…) return by themselves. Reduce Motion = still poses. Jest swaps the canvas for a plain view (`jest.setup.tsx`).
- `src/api/`: `schema.ts` is generated from `apps/server/openapi.json` (`npm run api:gen`); `client.ts` is the one place that calls the server. Never hand-write API shapes.
- Word test (O4–O7): `src/app/onboarding/word-test.tsx` (?page=A..D; the server says which page comes next, the app never knows the made-up words), `estimate.tsx` (count-up, "About level X", the "Were you guessing?" screen once). Rules: `docs/vocab-engine.md`.
- `src/app/onboarding/hello.tsx` (O0): the first screen of a fresh install: a very big Kai waves, Start opens O1. `startRoute()` sends an unfinished learner there. The splash picture is `assets/images/splash.png` (set in `app.json`; a change needs a new native build). The sample word on O2's lock screen comes from `src/onboarding/sample-word.ts` (the learned language, meaning in the spoken one).
- Reanimated does not load in Jest: put an entering animation in a small part like `components/fade-in.tsx` and mock it in `jest.setup.tsx`.
- `src/app/onboarding/` + `src/onboarding/`: question screens O1–O9. Answers live in `store.ts` until O9 saves them; route rules in `flow.ts`; the "finished" flag in `finished.ts`. The tabs layout sends an unfinished user to O1.
- Shared parts: `QuestionScreen` (top bar + footer), `OptionBox`, `ButtonPrimary`, `TextField`, `Icon` (Octicons; add names in `scripts/gen-icons.mjs`, then `npm run icons:gen`), `useLoad` (load + retry).
- `src/components/chat/`: the Kai chat parts (`KaiHeader`, `ChatBubble` with `**bold**`, `TypingBubble`, `ReplyOptions`, `Composer`, `DeckCard`, `RiseIn`). Every chat screen is built from these. `src/app/onboarding/kai.tsx` is the example; Kai's lines live in `src/onboarding/kai-script.ts` (English, built in); for another language the chat loads them from the server (`api.fetchKaiScript`) and reads every line through `makeScript` (own language first, then the picked chat language, with a translation line when Kai speaks the learned language).
- Kai types in every chat: send Kai's lines through `useKaiTyping` (`components/chat/use-kai-typing.ts`): dots for 0.8–1.2 s before each Kai bubble, one after another; show reply options only when it is not `busy`. Jest has typing off (`jest.setup.tsx`); `__tests__/kai-typing.test.tsx` turns it on.
- Kai's header state comes from `kaiStateFor()` in `kai-script.ts` (greeting, listening, thinking, speaking, making, celebrate, oops, waiting). Typed text in the onboarding chat goes to `api.kaiReply` (on the script → the step's answer; off → Kai's lines, then the question again); a failed reply takes the text as the answer.
- New words: `(tabs)/index.tsx` is the chat with Kai (lines come from the server, one by one behind a typing bubble). Small rules in `src/new-words/chat.ts`. Chat parts added for it: `TranslationToggle`, `ChatBubble` with a translation line, `Composer` with `mic={false}`, `WordCard` (a single word from Kai with "Add to Random Words N"). The red dot on the Review tab is `src/review/dot.ts` (set when a word is added, cleared when Review opens). The iOS tab bar floats over the screen: a tab screen with a control at the bottom keeps `layout.tabBarClearance` under it. Kai's state there is `newWordsKaiState()` in `new-words/chat.ts` (the shared `kaiStateFor()` plus `sleeping` after 2 quiet minutes). The screen keeps its own line queue (its tests check that rule's times); a tapped option rises with `RiseIn`. Scrolling to the top loads older messages (`api.fetchKaiChat(before)`).
- The Use it chat (`src/app/use-it/[id].tsx`) loads Kai's fixed lines from `api.fetchUseItScript()` (4 s at most, then the built-in English from `LINES` in `kai-script.ts`); it has the same translation switch as the other chats, and `api.useIt` / `api.askAboutWord` answer with `translations` when Kai speaks the learned language.
- Translation switch: one hook for every Kai chat, `useTranslation` (`components/chat/use-translation.ts`): the saved choice, the language code, `toggle`. Pass its `on` to `ChatBubble showTranslation`. A translation equal to the line is not shown. The onboarding chat sends `'target'` to `api.kaiReply` when Kai speaks the learned language, and gets `translations` back.
- Bold words: `**word**` in Kai's or the server's text is drawn by one part, `KaiText` (`components/chat/kai-text.tsx`; `plainText` takes the marks out). `ChatBubble` uses it for the line and its translation, `WordCard` for the example. Never split on `**` anywhere else.
- Reply options are the last item **inside** the chat's message list (after the last line and the typing bubble), never a block between the list and the composer. The list gets `chatMessagesGrow` and `useScrollToEndOnKeyboard(ref)`: a short chat keeps the options at the bottom, and when the keyboard opens the list scrolls to its end. Scroll a chat to its end only with `scrollChatToEnd(ref, optionsShown)`: with the options on screen it jumps with no animation, because on iOS a tap on a list that is still scrolling only stops the scroll and the tap on an option is lost.
- Voice in the chat box: `Composer` has the mic in every chat. Tap → the mic permission (`expo-audio`) → `VoiceRecorder` (`components/chat/voice-recorder.tsx`: X, wave, clock, Stop; 90 s at most) → `transcribeRecording` (`components/chat/voice.ts`, `api.transcribe`) → the text is added to the box. Small rules (file type, wave levels, clock) are plain functions in `voice.ts`. Jest mocks `expo-audio` in `jest.setup.tsx`. The box is `multiline`: it grows to six lines, then scrolls; Return still sends.
- Keyboard: Return closes it (`Composer`, `TextField`). Every chat's `ScrollView` spreads `chatScrollProps` (`components/chat/keyboard.ts`): a drag of the messages closes the keyboard, and the list has the testID `chat-messages`.
- Text direction: every text in a chat part is aligned by its own script with `directionStyle(text)` (`components/chat/direction.ts`): Persian, Arabic and Hebrew to the right, anything else to the left. Use it for any new text that shows a learner's or Kai's words.
- New words decks: a Kai line may have `decks`; `components/chat/deck-ideas.tsx` shows them under the bubble (three in a row to swipe with dots, one alone; only the chosen card once a deck is made). `DeckCard` has four states (`disabled` = an older idea), `showTranslation` and `inWordList`. Generate → `api.generateDeck` → `api.deckReady` (Kai says it once). The Review tab's red dot is `src/review/dot.ts` (kept on the phone, cleared when Review opens).
- Deck pictures and the deck card (2026-11-23): `DeckCard` has a fifth state, `drawing` (the words are made, the pictures are counted, not tappable). A card that can be opened (`ready`) has the open column on its right (testID `deck-open-column`, Figma "Deck card / Open column"); it is the one deck card for chat, onboarding and Progress (in a list pass `listed`: no JUST NOW, and the button is named "Open deck, <title>"). The drawing card's bar is timed (`pictureProgress`, `PICTURES_EXPECTED_MS` = 20 s): 0 to 90 % from the time the drawing started, 100 % when the run is really done; the count follows it. In a chat a deck's card shows once, at its newest place (`newestCards` in `new-words/chat.ts`). `api.waitForPictures` reads the deck until its picture run ends; onboarding (`kai.tsx`, step `drawing`) says Kai's script lines, New words uses `src/new-words/pictures.ts` (`useDeckPictures`) and the `deck_pictures` event. A card's picture is `imageUrl` (left out when there is none).
- A handler passed to `onPress` must not return a promise (`() => void save()`): the test library waits for it.
- Review: `(tabs)/review.tsx` (start A2 / done A9, with the server's summary) loads the round into `src/review/round-store.ts` and shows the round **inside the tab** so the tab bar stays; only the very first round opens `/review/round` full screen (Figma O12). `src/app/review/round.tsx` is both. It has Undo (last swipe, `api.undoSwipe`) and the streak card (`src/review/streak.ts`, once per review day). It walks the round (tap to flip, swipe or tap Hard / Know it / Easy). The card is `src/review/flashcard.tsx` (Figma: Flashcard · rules): picture or placeholder on top of both sides (half of the front, 42 % of the back: `card.pictureFront`, `card.pictureBack`), the word's size and its fixed lines from `wordLayout` in `word-size.ts` (one or two lines, never three; a word is never cut, the font gets smaller; the level square sits on the first line), the flip (each side turns by itself and rests with no 3D transform, or iOS draws it blurry), and the three swipe labels. The drag runs on the UI thread (`use-swipe.ts`, Reanimated + Gesture Handler; its rules are plain worklet functions in `swipe.ts`, tested in Jest). **A swipe never waits for the server:** the card leaves at once, the next card is already drawn under it, and `saver.ts` saves swipes one after another in the background (3 tries; a failed save puts the card back with `putBack` and shows "Could not save"). "BACK IN N DAYS" on the Easy label comes from the server (`api.fetchReviewRules`, `rules.ts`), never from the app. Only the top card and its facing side are readable by tests, Maestro and screen readers; `src/app/use-it/[id].tsx` is the Use it chat: before a good sentence typed text is checked (`api.useIt`), after it typed text is a question to Kai (`api.askAboutWord`). The card back shows Use it only when the server sends `canUseIt`. After the first round only: `src/app/intro/` (hard words, trial reminder, paywall), flag in `src/review/intro.ts`. The speaker's language is kept on the phone (`src/review/speech-language.ts`); every speaker button calls `sayWord` (`src/review/speak.ts`), never `Speech.speak` itself; a screen that shows a speaker calls `warmUpSpeech()` when it shows, so the first word does not start late; a speaker is darker while pressed (`speakerPressed`). An open round stays open: when the tab comes back into view (from another tab or from Use it) it keeps the round and only adds new cards at its end (`addToRound`); it loads again only when no round is open. The start screen shows `<Kai state="reviewing">` (Kai with flashcards), "N cards due today", "~M min" and the button under the text.
- The paywall sells nothing yet (no RevenueCat). Both buttons open the app.
- `src/auth/`: silent guest sign-in at start (`boot.ts`), Supabase client, session kept in SecureStore (`session-storage.ts`).
- `assets/kai/`: still SVG poses, for widgets only (screens use the live `Kai`). `assets/tabs/`: tab bar icons exported from Figma as PNG (1x, 2x, 3x). Native tabs take PNG or SF Symbols, not our SVG `Icon`.
- Deck page (`src/app/deck/[id].tsx`, Figma N7): a word row slides left (`SwipeRow`, PanResponder) to show the red Delete; each row also has the accessibility action "Delete" (tests use it). "Remove deck" asks with the system pop-up, then goes back. `api.removeCard` / `api.removeDeck` answer nothing (`204`) and throw on any other answer.
- `api.generateDeck` waits for the server's background job (it reads the deck again while the status is `generating`).

## Rules
- Expo changes every SDK. Read https://docs.expo.dev/versions/v58.0.0/ and https://docs.expo.dev/llms.txt before touching an Expo API.
- `ios/` and `android/` are generated (CNG). Never create or edit them. Native setup goes in `app.json` and config plugins.
- Widgets are native SwiftUI WidgetKit, added through the `expo-widgets` config plugin in `app.json` (a change there needs a new native build).
- The widget (`src/widgets/`, hard words only): `lockwords-widget.tsx` is the layout. It runs in the widget's own small runtime: no hooks, no network, nothing from outside the function; it only draws its `props`. `sync.ts` loads `api.fetchWidgetPlan()` and hands it over with `updateTimeline` (app start, back to the front); `timeline.ts` turns the server's plan into entries (pure, tested); `kai-files.ts` copies Kai's poses (one color for the lock screen, full color for the home screen; `assets/widget/`, made by `npm run widget:kai`) into the folder the widget can read; `pictures.ts` saves the word pictures there for the medium widget (once per picture, old ones deleted). Four sizes in the one layout file: `accessoryInline`, `accessoryRectangular`, `systemSmall`, `systemMedium`; the home sizes read `environment.colorScheme` (dark) and `widgetRenderingMode === 'accented'` (tinted), and their colors are typed in the layout because it cannot import the theme. A new prop for the home widgets is optional and left out when empty. The server decides words, order and looks; never sort or count here. A tap opens `lockwords://review?first=<id>`: `tapped.ts` keeps the id, the Review tab takes it and starts the round on that word (`api.fetchRound(undefined, first)`); a card with `lookOnly` has Next and no swipes. Jest gets a stand-in for `expo-widgets` (`jest.setup.tsx`). Limits: `docs/widget-limits.md`.
- A native package needs a new dev build (`npm run ios`). On this Mac start it with `LANG=en_US.UTF-8` in front, or `pod install` stops with "Unicode Normalization not appropriate for ASCII-8BIT" (found 2026-11-25). With the simulator locked, the command builds and installs but cannot open the app: unlock it first. `npm run ios` does not make `ios/` again when the folder is there: after a change in `app.json` (a new widget size, a plugin) run `npx expo prebuild -p ios` first, or the build silently keeps the old native setup (found 2026-11-25).
- Reanimated and Gesture Handler work in Jest (`jest.setup.tsx` + the jest `resolver` in `package.json`): animations jump to their end value. Change a shared value with `.set()` / `.get()`, not `.value` (the lint rule for the React Compiler).
- RN Testing Library v14: `render` is async. Write `await render(...)`.
- Every screen test covers its states: loading, empty, error, locked.
- iOS Keychain survives deleting the app: every secure key is in `SECURE_KEYS` (`src/auth/session-storage.ts`) and is cleared on a fresh install.
- Which server the app talks to: `src/config/backend.ts`. No settings = the cloud (a release build can never point at a Mac). The local stack = the three `EXPO_PUBLIC_*` values in `.env.local` (git-ignored, written by `npm run dev:up`; names in `.env.example`); set all three or none. `npm run start:cloud` runs the dev build against the cloud even when `.env.local` exists.
- Progress: `(tabs)/progress.tsx` (P1, top to bottom: the time switch `TimeTab` (`components/time-tab.tsx`: Today, gold when chosen, and In 3 months); the numbers and the legend from `api.fetchProgress` (`progress` today, `progress.future` in 3 months); one meadow with Kai (`nowMeadow` or `futureMeadow`); the words map (`GoalGrid`, a tick on mastered words); "You have N decks" with one short row per deck from `api.fetchDecks`: name, numbers, level chain, arrow) → `src/app/deck/[id].tsx` (P3 and N7, one page: filter chips counted in the app, Restore, "Review this deck" = `api.fetchRound(deckId)` + the round screen). There is no separate decks page and no hard words button or page (Hamid, 2026-11-23): hard words show on the one-time screen after the first round and under the Hard chip of a deck. The server still answers `hard` in `GET /v1/progress` and the full `GET /v1/hard-words` list.
- Maestro reads a row's accessibility label, not the texts inside a labelled row: put what a flow must check into the label.
- A word's color is `levelColor(stage, known)` from the theme, everywhere (new = lightest green, "I know it" = mastered = darkest). Never `levelColors[stage]` for a word. No red mark for hard words anywhere.
- The meadows: `src/progress/meadow.ts` lays out the blocks (pure; tree shapes from `docs/design/pixel-meadow.html`): `nowMeadow` (small: one tree per deck, one leaf per word, room for Kai on the right) and `goalMeadow` (big: the forest at the goal, three trees at least). `src/components/meadow.tsx` is the one component screens use; `meadow-canvas.tsx` draws and moves it with Skia in one picture per frame on the UI thread (grow in, wind, light, falling leaves; all numbers in its `MOTION`); `meadow-canvas.web.tsx` is the still picture for the browser and for Jest (`jest.setup.tsx`). Reduce Motion = a still picture. The goal grid (`src/components/goal-grid.tsx`) sizes its squares from the measured width: percent sizes do not work in a wrapping row.
- The word plan left the Progress tab on 2026-11-23. `src/new-words/pending.ts` and its use in the New words tab are left over (nothing fills it now).
